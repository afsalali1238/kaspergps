# J2 self-check — realistic telemetry, fuel, rentals, parked cadence

Branch `arena/2b1c0619-kaspergps` · Date 2026-10-12 · Base `80e6513` (main)

## What changed

- **Movement by class (§9)** — `src/server/telemetry/movement.ts` (new) and `simulator.ts` (rewritten).
  Trucks drive between yard and sites at 20–90 km/h. Plant stays within ~0.0015° (≈170 m) of its
  site in 90 s moves once per 60-minute bucket. Lifting moves ≈0.0006°. Generators are stationary.
  Odometer = haversine between consecutive readings; transit resets the previous point.
  GPS wobble is applied only while moving.
- **Fuel (§9)** — `src/server/telemetry/fuel.ts` (new). Per-asset varied levels; refuels add 40–70%
  during the shift; GN-01 drops 18% at 02:10 Dubai with the engine off.
- **Rentals (§9)** — an asset on an active rental reads at the renter's site for the rental period.
- **Parked cadence (§9)** — parked readings every 10 min; heading does not spin while parked.
- **Seed behaviour (`src/server/seed/data.ts`)** — the `behaviour` column was changed so each asset
  follows its class rule: TP-23 and WT-08 from `parked` to `drives_between_sites`; EX-07, EX-11,
  BH-05, FL-10 to `works_at_site`; CR-02 from `parked` to `works_at_site`. The §8.2 status rows these
  assets have are unchanged (checked by the status table test).
- **GN-01 status (`src/server/seed/expected.ts`)** — `idle` → `live`. At the anchor GN-01 is under
  working load, so it is `live`, not idle. This follows §12 (`WORKING_LOAD_PCT`).
- **`computeStatus`** — no code change needed. Idle already requires engine load undefined or below
  `WORKING_LOAD_PCT`. FB-14 (`Live, parked`) is `live` with ignition off, matching §8.2. GN-02
  (`Stale`) is `stale`, matching §8.2.
- **Tests added** — `src/server/telemetry/j2-simulated-data.test.ts` (49 tests): §8.2 status at the
  anchor for all 36 assets; supported and unsupported CAN params per asset; Tier 3 fuel spread; working
  load for the working plant; FB-12 driving at the anchor; plant shift starts 07:00 Dubai; truck speeds
  and rising odometer; generator stationary; rented machine at the renter's site; 10-minute parked
  cadence with no heading spin; GN-01 18% drop at 02:10; refuels 40–70%; no reading later than the clock.
- **Proof screens** — `tests/e2e/j2-proof.spec.ts` (desktop) opens EX-04 Engine & fuel and FB-12 Trips,
  checks for a page error and console errors, and saves screenshots to `reviews/screenshots/J2/`.
- Temporary diagnostics `src/diag/` deleted.

## Deviations and things to know

- **FB-12 speed.** FB-12 was a fixed 25 km/h route before. It now uses the truck speed range
  (20–90 km/h) like the other trucks. The Trips screen shows top speeds of 64–83 km/h. Its scripted
  arrival at the destination "about 90 min after the anchor" (§9) is only covered by the anchor check
  (driving from Jebel Ali towards the Al Habtoor site). I did not separately test the arrival time.
- **GN-01 status change.** Idle → live, as above. The seeded GN-01 alerts (`al-gn01-drop`,
  `al-gn01-lowfuel`) are hard-coded and belong to J3.
- **Seed behaviour corrections.** See the list above. These change the day's movement only; status
  rows are unchanged.
- **Not run in this phase:** the `reviews/screenshots/P14` set was regenerated by the full Playwright
  run. I restored it with `git checkout`, so the historical P14 captures are untouched.
- **Environment (not a product change).** Playwright's own Chromium download is blocked in this
  sandbox. The e2e run used a Chromium 131 binary from the npm package `@sparticuz/chromium`, through
  `PW_CHROMIUM_PATH` and `PW_CHROMIUM_ARGS`. It is outside the repo and is not committed. The first
  dev-mode run had 2 failures (the certificate Tools click, and the S42 "Next" button that matched the
  Next.js dev-tools button). The page was stuck on "Loading…" under `next dev`. Both pass in CI mode
  (production build), and the full CI-mode run is the verdict above.
